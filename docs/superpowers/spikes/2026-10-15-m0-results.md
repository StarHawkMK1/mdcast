## 계획 작성 중 발견한 사실 (구현에 반영됨)
- MD 리더 형식은 `markdown-markdown_in_html_blocks` 여야 `<table>…</table>` 이 RawBlock 하나로 남는다 (기본 `markdown` 은 태그별로 쪼갬).
- HTML 표에서 머리행을 가로지르는 rowspan 은 `<thead>`/`<tbody>` 를 명시해야 pandoc AST 에 보존된다. → Skill 작성 규칙에 추가 필요.
- Typst 는 한글 폰트 이름("맑은 고딕")을 인식하지 못한다 → 영문 패밀리명("Malgun Gothic")으로 바꾸는 별칭표 필요.
- Typst figure 는 기본으로 "표 1:" 보충어를 붙인다 → `set figure(numbering: none)` 로 끄고 캡션 번호는 mdcast 가 매긴다.
- Typst 의 `#include` 는 별도 스코프라 정의를 공유하지 않는다 → 본문 앞에 `#import "mdcast.typ": *` 와 `#show: conf.with(cfg)` 를 붙인 단일 main.typ 를 만든다.
- 표 머리행 정렬은 AST 셀 alignment 로 지정하면 docx(jc)·typst(table.cell align) 모두에 반영된다.
- pandoc docx 는 캡션에 자동 번호를 붙이지 않는다 (번호는 mdcast 필터가 담당).

## S1 상세

**상태: 보류 (미실행).** 한컴 자동화 보안 모듈(`FilePathCheckerModule`)이 이 PC 에 등록되어 있지 않아, 사용자 결정으로 COM 실행과 한글 수동 열기는 M2 이전으로 미뤘다. 이 문서의 스크립트는 작성만 되었고 아직 한 번도 실행되지 않았다.

**실행 절차 (M2 이전에 수행):**
1. 보안 모듈 등록: `FilePathCheckerModuleExample.dll` 을 한컴 개발자 사이트에서 받아, 레지스트리 문자열 값 `HKEY_CURRENT_USER\Software\HNC\HwpAutomation\Modules\FilePathCheckerModule` 을 DLL 전체 경로로 설정한다.
2. `uv run python spikes/s1_hwpx/make_seed.py .test-output/s1/seed.hwpx` 로 한글에서 빈 hwpx 를 만든다 (`.test-output/s1/` 선행 생성). 보안 대화상자가 파일마다 뜨는지, 보안 모듈이 실제로 필요했는지 기록한다.
3. 엔트리 목록을 확인한다: `uv run python -c "import zipfile; z=zipfile.ZipFile('.test-output/s1/seed.hwpx'); [print(i.filename, i.compress_type) for i in z.infolist()]"`. `mimetype`(compress_type 0, stored), `Contents/header.xml`, `Contents/section0.xml` 포함 여부를 여기에 붙인다.
4. `uv run python spikes/s1_hwpx/patch_hwpx.py .test-output/s1/seed.hwpx .test-output/s1/patched.hwpx` 로 section0.xml 에 문단 3개를 붙이고, header.xml 의 첫 `charPr` height 를 1.5 배로 바꾼다.
5. `uv run python spikes/s1_hwpx/verify_open.py .test-output/s1/patched.hwpx` 로 COM Open 결과와 텍스트를 확인한다. 기대값은 `Open -> True` 와 `TEXTS` 세 줄 (`<>&` 포함) 이다.
6. `.test-output/s1/patched.hwpx` 를 탐색기에서 더블클릭해 한글에서 수동으로 연다. 기대값은 "파일이 손상되었습니다" 또는 "복구" 대화상자가 없고 문단 3개가 보이며, 글자 높이 변경이 반영되는 것이다. 스크린샷은 `.test-output/s1/opened.png` 로 저장한다 (git 제외).

**엔트리 목록, 보안 모듈 필요 여부, 대화상자 문구:** 미실행이라 아직 기록할 값이 없다. 위 절차 2–3 에서 채운다.

**접근 방식 메모:** 이번 스파이크는 spec §10 S1 의 "코드로 생성한 최소 hwpx" 보다는, 한글로 저장한 seed 의 컨테이너(`mimetype`, `header.xml`, `section0.xml` 외 엔트리)를 재사용하고 `section0.xml` 을 재작성하며 `header.xml` 의 값 하나를 수정하는 방식이다. 이는 spec §4.1 의 "reference.hwpx 그릇 재사용, section0.xml 재생성" 접근에 더 가깝다. 따라서 PASS 되어도 "최소 hwpx 를 처음부터 생성해도 열린다"는 뜻은 아니다.

**판정 기준:**
- **PASS** (COM `Open -> True`, 텍스트 존재, COM 과 수동 열기 모두 오류·복구 대화상자 없음): M2 는 spec §4.1 의 "reference.hwpx 그릇 재사용, section0.xml 재생성" 접근을 쓴다.
- **FAIL**: 정확한 대화상자 문구를 기록한다. `patch_hwpx.py` 의 `STRIP` 에서 `"linesegarray"` 를 빼고 한 번 더 재시험한다 (linesegarray 를 유지). 그래도 실패하면 spec §10 의 대체안, 즉 한글로 저장한 컨테이너에 대한 최소 편집으로 범위를 줄이는 방안을 기록한다. 이는 M2 시작 전에 사용자와 결정할 사항이다.
