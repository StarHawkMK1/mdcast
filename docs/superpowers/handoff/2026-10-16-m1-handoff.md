# mdcast 핸드오프 — M1 완료 시점 (2026-10-16)

다음 작업자(사람 또는 에이전트)가 이 문서만 읽고 이어서 작업할 수 있도록 현재 상태, 남은 일, 사용자가 직접 해야 할 일을 정리한다.

- 저장소: https://github.com/StarHawkMK1/mdcast (public, 기본 브랜치 `main`)
- 설계 스펙: `docs/superpowers/specs/2026-10-15-mdcast-design.md` (최상위 기준)
- M0–M1 구현 계획: `docs/superpowers/plans/2026-10-15-mdcast-m0-m1.md`
- M0 실험 결과: `docs/superpowers/spikes/2026-10-15-m0-results.md`
- 로컬 폴더 이름은 `doccast` 이지만 패키지·CLI·저장소 이름은 모두 `mdcast` 다. 폴더 이름은 나중에 바꿔도 된다.

## 1. 현재 상태

**M1 (코어 + MD → docx/pdf 내보내기) 완료.** 계획의 23개 태스크마다 구현, 태스크 리뷰, 수정을 거쳤고, 브랜치 전체 최종 리뷰(13건)와 그 수정까지 반영해 main 에 push 했다.

| 항목 | 상태 |
|---|---|
| 테스트 | `uv run pytest -q` → 318 passed, 1 skipped / `--run-visual` 통과 / `ruff check` 깨끗 |
| 환경 | Windows 11, Python 3.12, uv 0.8.4, pandoc 3.9 (pypandoc-binary), typst-py 0.15, Microsoft Word 있음, 한컴오피스 2020 있음, LibreOffice 없음 |
| CLI | `mdcast convert`, `mdcast template list/describe/validate` |
| 출력 | docx(pandoc + python-docx 후처리), pdf(pandoc → Typst) |

### 구조 요약 (`src/mdcast/`)
- `pipeline.py`: `convert(source, targets, template, options) -> Result`. 바이트 입출력이며, 대상 형식마다 AST 사본을 만들어 필터와 writer 를 따로 돌린다. 한 형식이 실패해도 다른 형식은 만든다.
- `readers/md.py`: MD 를 pandoc AST 로 읽는다(`markdown-markdown_in_html_blocks`). frontmatter 를 분리하며, 깨진 YAML 이면 `FRONTMATTER_INVALID` 경고 후 계속한다.
- `templates/`: 템플릿 해석 순서는 경로 → `./.mdcast/templates` → `~/.mdcast/templates` → 내장 `default` 이다. 스키마 검증은 거부하지 않고 잘못된 값만 버린 뒤 상위 값으로 대체한다. `ResolvedTemplate.explicit` 은 사용자 yaml 에 명시된 값만 담는다.
- `filters/`: pagebreak, table-variant(`<!-- table: 이름 -->`), numbering(제목·캡션 번호, 제목에 `mdcast-number` 속성).
- `writers/docx/`: styles(스타일 매핑·모양), headers(머리말·꼬리말 `{{필드}}`), numbering(개조식 목록 기호), tables, meta(core·custom properties).
- `writers/pdf/`: Typst 설정 JSON 과 내장 `pdf.typ` 로 조판한다. 글꼴 대체 경고를 내고 Noto Sans KR 을 번들한다.
- `writers/images.py`: 이미지 현지화. 로컬·원격(20 MiB, 시간 제한) 이미지를 바이트로 형식 판별하고, 실패하면 자리표시로 바꾼다(PDF 만 엄격 판별).
- `report.py`: 이벤트 수준(info/warn/error)과 안정 코드(`Codes`).

### 핵심 원칙 (스펙 §0.3·§0.4)
- **무거부(no-reject):** 어떤 입력이든 출력을 만들고, 문제는 경고 이벤트로 알린다. `tests/test_no_reject.py` 가 이 계약을 지킨다.
- **같은 모양:** docx 와 pdf 가 같은 회사 양식처럼 보여야 한다. `template.yaml` 하나가 두 형식을 함께 결정한다.

## 2. 이번 세션 이후 정리한 minor 항목

M1 끝에 미뤄 두었던 사소한 항목 중 사용자 결정 없이 고칠 수 있는 것을 고쳤다.

| 항목 | 내용 | 커밋 |
|---|---|---|
| `convert()` 준비 단계 | 템플릿 해석, 필드, 생성 정보, 임시 폴더 준비가 실패하면 예외를 던지지 않고 리포트로 알린다. 템플릿이 실패하면 내장 default 로 대체(`TEMPLATE_INVALID` warn)하고, 필드·생성 정보가 실패하면 빈 값으로 대체(`RENDER_WARNING`)한다. 내장 default 나 임시 폴더까지 실패하면 `RENDER_FAILED` error 를 내고 출력 없이 Result 를 돌려준다. | 72b22d4 |
| docx 보조 스타일 | `styles.body.docx` 등을 회사 스타일(예: "본문")에 매핑하면 pandoc 의 First Paragraph·Compact·Image Caption·Caption 도 그 스타일을 기반(basedOn)으로 삼는다. 각자의 차이(Compact 의 좁은 간격)는 유지된다. | b5b6e4e |
| 각주 안 목록 | 각주·미주 안의 목록도 개조식 기호를 받는다. 회사 docx 템플릿에 들어 있는 스타일 연결 번호는 여전히 건드리지 않는다. | b5b6e4e |
| `mdcast-number` 속성 | 제목 번호 속성 테스트를 추가했다. 값이 보이는 번호와 같은지, `unnumbered`, 패턴 밖 수준, 하위 수준 초기화, 출력 본문에 노출되지 않는지를 본다. 동작 변경은 없다. | 21ee33d |
| 인라인 이미지 id | 자리표시가 된 인라인 이미지(`{#id}`)도 id 를 유지한다. 이제 링크가 있어도 PDF 가 실패하지 않는다. | b13225b |

남은 사소한 항목은 4절(M4 typst 타임아웃, M5 원격 이미지 하드닝, PDF 줄 간격, `figures.*` 적용)에 적었다.

## 3. 사용자가 직접 해야 할 일

### 3.1 확인 (M2 시작 전에 권장)
1. **PDF 시각 골든 승인:** `tests/golden/pdf/korean-report-p1.png` 를 연다. 머리말 오른쪽에 `2026년 4분기 사업계획` 과 그 아래 선이 있는지, 1쪽에 `추진 배경` 과 □ ○ 기호만 있는지, 꼬리말이 `1 / 3` 인지 본다. 이상하면 원인을 고친 뒤 `MDCAST_UPDATE_GOLDEN=1 uv run pytest tests/test_visual.py --run-visual` 로 다시 만든다.
2. **개조식 목록 Word 확인(S4):** 최종 리뷰에서 들여쓰기가 바뀌었으므로 파일을 다시 생성해 확인한다.
   ```
   PYTHONPATH=tests uv run python -c "from pathlib import Path; import tempfile; from helpers import build; from mdcast.types import Format; from mdcast.writers.docx import write_docx; p=Path('.test-output/m1'); p.mkdir(parents=True, exist_ok=True); doc, ctx = build(Path(tempfile.mkdtemp()), '- 하나\n    - 둘\n        - 셋\n            - 넷\n\n1. 첫째\n    1. 둘째\n        1. 셋째\n', Format.DOCX); (p/'lists.docx').write_bytes(write_docx(doc, ctx))"
   ```
   `.test-output/m1/lists.docx` 를 Word 에서 열어 다음을 확인한다: □ ○ - · / 1. 가. 1) 기호가 보이는지, `가.` 뒤 간격이 적당한지, 손상 안내가 없는지, 글꼴이 맑은 고딕인지. 결과는 `docs/superpowers/spikes/2026-10-15-m0-results.md` S4 행에 적는다.
3. **표 Word 확인:** `.test-output/m1/make_tables.py` 를 `uv run python` 으로 실행하면 `.test-output/m1/tables.docx` 가 나온다. Word 에서 표 종류별 서식, 머리행 반복·굵게, 손상 안내 여부를 본다. 이 스크립트는 git 에 없는 로컬 파일이다. 없으면 `tests/test_docx_tables.py` 의 예시로 만들면 된다.
4. **최종 결과물 눈 확인:** `uv run pytest tests/test_e2e.py` 를 실행하면 `.test-output/e2e/` 에 kitchen-sink·korean-report·edge-cases 의 docx/pdf 가 나온다. `uv run python scripts/render_pages.py .test-output/e2e/korean-report.docx .test-output/e2e/korean-report.pdf` 로 PNG 를 만들어 docx 와 pdf 가 같은 양식으로 보이는지 비교한다.

### 3.2 M2 전에 반드시
5. **S1 hwpx 실험 실행:** 한컴 자동화 보안 모듈(`FilePathCheckerModule`)을 등록해야 하므로 사용자만 할 수 있다(DLL 설치·레지스트리 변경). 절차와 판정 기준은 `docs/superpowers/spikes/2026-10-15-m0-results.md` 의 "S1 상세" 에 있다. 결과에 따라 M2 의 hwpx writer 접근 방식(그릇 재사용 + `section0.xml` 재생성, 또는 최소 편집)이 정해진다.

### 3.3 결정·정책 (스펙 §11)
6. **회사 오픈소스 공개 승인:** 스펙에는 공개 전에 받기로 되어 있었으나 저장소를 public 으로 만들었다. 승인 절차가 필요하면 진행하고, 필요하면 저장소를 private 으로 돌린다.
7. **커밋 작성자 이메일:** 지금까지의 모든 커밋에 회사 주소(`git config user.email`)가 공개되어 있다. 바꾸려면 `git config user.email` 을 바꾸고, 과거 커밋까지 고치려면 history 를 다시 쓰고 force push 해야 한다(되돌리기 어려움, 사용자 판단).
8. **실제 default 템플릿 내용:** 스펙 §11 에 따라 작성자가 제공한다. 그 전까지는 중립 스타터(`src/mdcast/builtin_templates/default/`)를 쓴다.
9. **회사 템플릿 시험:** 실제 회사 reference.docx 로 `template.yaml` 의 `styles.*.docx` 매핑을 시험해 본다. 결과에 따라 스타일 매핑의 부족한 점을 찾는다.
10. 한컴 공개 문서 출처 표기 요구 여부, 단계 1 배포 채널(GitHub 비공개 vs 회사 GitLab), 공개 전 점검(코퍼스 기밀 여부, 회사 로고·양식·사내 폰트 미포함).
11. (선택) 로컬 폴더 이름 `doccast` → `mdcast`.

## 4. 다음 할 일 (개발)

스펙 §9 의 마일스톤 순서를 따른다. 마일스톤마다 새 구현 계획을 쓴다. 전체를 한 번에 계획하지 않는다.

### M2 — hwpx 내보내기 (S1 결과가 먼저 있어야 함)
- 새 계획 파일: `docs/superpowers/plans/<날짜>-mdcast-m2-hwpx.md`. superpowers:writing-plans 로 작성한다.
- 범위: `writers/hwpx/` writer(그릇 hwpx 재사용, `section0.xml` 생성, `header.xml` 의 스타일·글자 모양), 한글 COM 검증 루프, 시각 비교.
- 확인할 사실(스펙 §10): hwpx 쪽 나눔·쪽 번호 컨트롤의 정확한 XML 표현.
- 이미 있는 스파이크 스크립트: `spikes/s1_hwpx/` (`make_seed.py`, `patch_hwpx.py`, `verify_open.py`).
- 내장 default 템플릿에 `reference.hwpx` 그릇을 추가하고, `template.yaml` 의 hwpx 매핑 스키마를 확정한다.

### M3 — 가져오기 (docx/hwpx/pdf → MD)
- 제목의 `mdcast-number` 속성으로 번호를 떼어 내는 역변환 필터, 개조식 휴리스틱, 왕복 테스트, PDF 복원율 임계값.

### M4 — 다이어그램·수식·견고성
- Mermaid·PlantUML 렌더, hwpx 수식 이미지, 캐시, `doctor`.
- **typst 컴파일 타임아웃(스펙 §5.5, 60초):** 지금은 프로세스 안에서 컴파일하므로 멈추면 변환도 멈춘다. 작업 프로세스로 분리해야 한다.

### M5 — 패키징·인터페이스
- MCP 서버(로컬 stdio, 도구 5개), Skill, `template init`, `skill install`, 라이선스 고지, 배포 문서.
- 원격 모드를 고려한다면 이미지 경로 하드닝이 필요하다. 지금은 `base_dir`/cwd 기준 로컬 읽기만 허용하므로, 원격 모드에서는 경로 제한과 SSRF 차단을 추가해야 한다(스펙 부록 A).

### 기능 보류 목록 (M1 에서 의도적으로 미룸)
- `figures.max_width` / `figures.align`: 스키마 검증만 하고 writer 에는 아직 적용하지 않는다.
- 머리말/꼬리말 `logo`, PDF 셀 세로 정렬(docx 만 적용), docx 캡션 위치(pandoc 기본: 표 위, 그림 아래), 표 셀 안의 중첩 표.
- PDF 의 목록·표 줄 간격이 docx 보다 좁다. 지금은 허용하고 있으며, 회사 양식 시험 때 맞춘다.
- 골든 XML 스냅숏 테스트(스펙 §7.6).

## 5. 작업 방법 메모

- 테스트: `uv run pytest -q`(5–10분), `uv run pytest tests/test_visual.py --run-visual -q`(이 PC 의 맑은 고딕 기준 골든), `uv run ruff check src tests`.
- 수동 확인용 산출물은 `.test-output/` 에 둔다(git 제외).
- 줄바꿈은 `.gitattributes` 로 LF 로 통일한다. `tests/fixtures/md/edge-cases.md` 는 CRLF·LF 가 섞인 그대로 둔다(`-text`).
- 사용자에게 보이는 메시지는 한국어로 쓴다. 새 이벤트 코드는 `report.Codes` 에 추가하고 README 에 적는다.
- M1 진행 중 내린 판단(무거부 검증 강화, I2 명시값 우선, 이미지 상한 등)은 커밋 메시지와 코드 주석에 남아 있다. 핵심만 추리면 다음과 같다.
  - 템플릿 값이 잘못되면 거부하지 않고 상위 값을 쓴다.
  - 사용자 reference.docx 를 쓰면 yaml 에 명시한 모양만 덮어쓴다.
  - frontmatter 의 상대 `template:` 경로는 문서 폴더를 기준으로 한다(`--template` 은 현재 폴더 기준).
  - docx 에는 pandoc 제목 블록을 넣지 않는다.
  - 이미지 형식 엄격 판별은 PDF 에만 적용한다.
